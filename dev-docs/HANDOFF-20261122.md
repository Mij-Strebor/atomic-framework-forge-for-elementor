## How to see bug P-AFF-001 and confirm the fix

**Use a throwaway test site.** Reproducing the bug damages that site's Elementor variables on purpose.

**A. See the bug (unfixed code)**
1. In PowerShell:
   ```powershell
   cd E:\projects\plugins\aff
   git checkout master
   ```
2. In Elementor's editor, open the **Variables** panel and create two or three variables, e.g. a color `brand-test`.
3. In AFF: **Sync** from Elementor, so AFF imports those variables.
4. In AFF **Fonts**, add a variable whose value contains quote marks: `"Open Sans", sans-serif`.
5. **Commit to Elementor.**
6. Edit any one variable in AFF and **commit again.**
7. Back in Elementor's Variables panel: with the bug, the variables you created in step 2 are **gone**, or the panel can't load them.
   (Claude hasn't seen exactly how Elementor displays the damaged data. Note what you see.)

**B. Confirm the fix**
1. Restore the site's variables: recreate them in Elementor, or start a fresh site.
2. In PowerShell:
   ```powershell
   cd E:\projects\plugins\aff
   git checkout bugfix/commit-data-loss-and-security
   ```
3. Repeat steps A2 to A6.
4. **Expected:** every Elementor variable is still there, and the font value shows correctly with its quote marks.
5. Claude can also check the saved data directly through the MCP once it's connected.
